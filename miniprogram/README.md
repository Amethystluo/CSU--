# 中南大学交通规划小程序

在微信开发者工具中选择"导入项目"，项目目录选择本目录即可。

> **务必勾选**：详情 → 本地设置 → 「不校验合法域名、web-view(业务域名)、TLS 版本以及 HTTPS 证书」。
> 否则实时天气接口会被拦截（拦截也不影响其他功能，会自动退回手动档位）。

## 页面

- **首页**：功能宫格入口 —— 预测热度、少人路线、中南农场、校园吐槽、事件与校历、路况管理。
- **预测热度**：2D 热度图；3D 按钮提供移动端的透视视图入口。
- **事件与校历**（`pages/event`）：**事件**是一等公民，不写死在页面里 ——
  每条记录「名称 / 类型 / 日期时间 / 场馆 / **谁参加**（年级 × 专业，可叠加）/ **预计多少人**」，
  保存后立刻算出"涉及多少班、多少栋宿舍、几点入场离场"；校历可以录**放假**与**调休**
  （例如周六补周四的课）。默认是空的，点「载入示例」看三条典型场景。
- **少人路线**：起点支持 **自动定位 / 从 58 个常用地点选 / 地图点选**，
  终点支持 **列表选 / 地图点选**。选好后吸附到最近的路网节点，再按所选走法规划路线。
  **自动定位会显示地点名而不是经纬度**（如 `南校区6舍`、`南校区5舍附近`、
  `距第二教学楼约 880 米`），小字补充校区 / 类型 / 精确距离 / 吸附偏移。
  另外支持**特殊情况与实时路况**：

  | 功能 | 说明 |
  |---|---|
  | **选日期 + 选时段** | 先选**具体某一天**（`<picker mode="date">`，默认今天），再选那一刻：按当前时间 / 当天最忙 / 整周最高峰 / 当天各换课时刻。**课表按星期几分开算，所以每天形状不同**：周三下午几乎没课、周四晚上几乎没人 |
  | **当天事件** | 列出那天的活动（校运会 / 双选会…），可逐个**计入或排除**；活动的入场/离场时刻会出现在"选择时段"里，选中就把活动流量叠加到课表基线上，路线与热度随之变化 |
  | 三种走法 | **时间最短**（电动车实际骑行时间）/ **少人优先** / **距离最短**，点对比表可切换 |
  | 天气 | 联网获取实时天气（Open-Meteo），也可手动指定；雨天会减速并**加剧拥堵** |
  | 直接封路 | 管理员/调度直接改道路信息；流量自动重分配到替代路径 |
  | **实时路况上报** | 选路后选情况类型（施工封路 / 事故障碍 / 异常拥堵 / 有交警）提交 |
  | **交警绕行** | 开启后按「被拦下平均耽误 3 分钟」折算代价，能绕就绕；必经之路上会如实提示 |
  | 拥堵预测 | 全网拥堵指数、明显变堵路段数、受影响最重的路段 |
  | 目的地搜索 | 按名称/编号/校区搜索 58 个地点，可切换「全部/宿舍/教学点」 |
  | 实时定位 | 蓝色「我的位置」跟随移动并显示所在地点；起点是定位来的则位移超 40 米自动重规划 |
  | 路线箭头 | 路线上画行进方向箭头 |
  | 拥堵彩蛋 | 极堵路段上的可点节点，弹出趣味提示（纯娱乐，不影响计算） |

- **地图点选页**（`pages/pick`）：单独的全屏二级页面，四种模式（封闭 / 上报 / 起点 / 终点）。
  **全屏且不滚动**，所以触摸坐标永远准确；选中的路会即时高亮，确认后才回传上一页。
  **地图可拖动 + 双指捏合缩放**（0.7×~4×，默认 1.6×），拖动范围夹紧不会拖丢，
  「全览」回全局视野、「复位」回初始视野；拖完/捏合之后点选仍然精准。

- **路况管理**（`pages/admin`）：审核用户上报 —— 标为**属实**才会进入路线计算，
  标为**不属实**直接丢弃，待核实只在地图上以虚线空心标记提醒。可一键核实全部待审。

  实测：南校区6舍→数统院，距离最短的路少走 105 米却因穿过最忙走廊多花 5 分钟；
  再叠加"中到大雨 + 封一条路"，最快路线从 9.0 分变成 14.5 分；
  开启「绕开交警」后多花 2.5 分钟绕开查车点。

- **中南农场**（`pages/farm`）：校园休闲小游戏 —— 种菜、收获、卖学币、升级解锁高级作物，
  可摸奖。数据存本机 `wx.storage`，纯娱乐，不影响交通计算。
- **校园吐槽**（`pages/complain`）：通勤吐槽 / 建议的匿名留言板，支持发布、点赞、
  最新/最热排序、复制与删除，数据存本机 `wx.storage`。

## 上报数据怎么同步给其他用户

**默认是本机存储**，只有这台设备看得到。要真正多用户共享，开通微信云开发即可：

1. 开发者工具 → 云开发 → 新建环境，记下**环境 ID**；
2. 云开发控制台新建集合 `reports`，权限设为「所有用户可读，仅创建者可写」；
3. 把环境 ID 填到 `utils/reportStore.js` 的 `CLOUD_ENV`，**代码无需其他改动**。

未开通时功能照常，页面会如实标注存储后端。详见项目说明文档 7.7 节。

## 路线功能是怎么算的

1. `data/route-graph.js` 是构建阶段生成好的紧凑路网（420 节点、568 路段、58 个常用地点，
   含逐边几何，约 42 KB），由 `tools/build-route-graph.js` 从 `data/` 下的原始数据编译而来——
   **原始数据不需要打进小程序包**。
2. `utils/router.js`：投影、最近节点/路段吸附、电动自行车速度模型、
   **速度–密度自洽迭代**（占用率 ∝ 流量 ÷ 车速）、三种代价的 Dijkstra、交警等效延误。
3. `utils/scenario.js`：天气档位系数 + **增量分配法**流量重分配，产出新的热度图数据。
4. `utils/reports.js` / `utils/reportStore.js`：上报模型、审核规则、
   「上报 → 生效路况」聚合，以及本机/云端两种存储适配器。
5. 路线页底图用不带热度的 `campus-map.svg`，热度层由画布按当前情景的占用率动态绘制，
   所以任何情景都能立刻看到新的热度分布。
6. `utils/render.js` 统一两个页面的画布绘制；`utils/session.js` 让点选页拿到与路线页同样的
   情景参数；`utils/pickBus.js` 负责点选结果回传。

**要调车速、拥挤系数、雨天系数或交警延误，只改 `utils/router.js` 与 `utils/scenario.js` 里的表。**

node tools/test-router.js            # 路由算法与地点命名测试（67 项）
node tools/test-scenario.js          # 情景引擎测试（38 项）

node tools/build-landmarks.js        # 底图标注 -> data/landmarks.js

## 注意

- 微信小程序不能直接运行本地 `map-3d.html`，真正的 Three.js WebGL 版本需要部署到 HTTPS 域名后
  通过 `web-view` 接入。本目录中的 3D 按钮先提供无需域名即可导入运行的透视地图版本。
- 天气数据来自 [Open-Meteo](https://open-meteo.com/)（CC BY 4.0），页面已标注来源。
  `wx.request` 需要域名白名单，正式发布建议用云函数代理（详见项目说明文档 7.4）。
- 原始数据文件（`traffic-flow.json`、`graph-*.json/geojson`、`buildings-3d.geojson`）
  已在 `project.config.json` 的 `packOptions.ignore` 中排除，只作为构建素材留在磁盘上。
  排除后小程序包约 660 KB。
