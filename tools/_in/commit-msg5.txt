把「事件」变成一等公民：谁参加 / 在哪 / 多少人 / 调休

用户要求：事件要是一个独立的东西而不是写死在页面里 —— 每条记「什么活动、什么时候在哪、
谁参加（按院系还是按年级，可能两个都要）、预计多少人」，因此改变路径，并能区分调休。

先确认"按院系/年级选人"有没有数据支撑
- 数据里没有院系字段，但班级名带着信息：智能2606（专业+26级）、口腔医学（5+3）2402、
  土木2505（天佑班）。1090 个班全部解析成功 -> 4 个年级 / 137 个专业 / 30,948 人。
- 界面按专业名前两字粗分成 100 个"学院"方便勾选（机械 = 机械/机械类/机械D/机械T），
  展开还能只勾某个专业；事件里存的始终是精确专业名。粗分规则写在数据文件里，注明不是官方院系表。

新增两份构建产出的索引
- tools/build-landmarks.js -> data/landmarks.js（11.0 KB）：从底图 SVG 的 121 个标注里
  提出 124 个地标（去掉指北针/比例尺/片区名）并吸附到最近路口。
  「校运会 -> 新校体育场"鸟巢"西门」「双选会 -> 南校礼堂」都有真实坐标。
- tools/build-people-index.js -> data/people-index.js（30.6 KB）：班级名 ->
  (专业, 年级, 宿舍) -> 人数，1090 班聚合成 944 行。关键取舍：先按宿舍聚合再跑最短路，
  宿舍只有 35 个节点，一次事件只需 35x2 次 Dijkstra（实测 17 ms）。

新增逻辑与页面
- utils/events.js：事件模型（名称/类型/日期/起止/场馆/年级x专业/预计人数）+ 人群解析 +
  出行窗口（开场前 N 分钟入场、结束后离场）+ 逐窗口流量叠加与缓存。
- utils/calendar.js：放假 / 调休的覆盖表，决定"这天按哪天的课表算"。
- utils/eventStore.js + data/schedule.js：事件与校历的存取（本机存储）；默认空空如也
  （不编造学校活动），可一键载入示例。
- pages/event：事件与校历页 —— 增删改、年级多选、学院/专业多选、场馆选择、预计人数、
  实时试算"选了谁/多少人/几栋宿舍/几点入场"，以及放假与调休的增删。

路线页接入
- 加「当天事件」卡片，逐个勾选计入/排除；活动的入场/离场时刻会加进"选择时段"列表
  （key = ev:分钟:类型），选中即叠加到课表基线上；口径文案写清来源。
- 日期口径改成走校历：放假 -> 没有课（但活动仍然有效）；调休 -> 按指定星期几的课表算。
- 「当天最忙」的候选 = 课表换课时刻 + 活动入场/离场时刻。

修掉两个真 bug（都是这轮新写的测试抓到的）
- 勾一个"学院"后 chip 选中态不刷新（patch 没重建 groups），导致"再点一次取消"失效、
  点单个专业反而变成新增。
- 勾/取消活动后没有重算情景，热度图不变；且重列时刻会把用户当前视角弹回"自动"。
  改成 initTimeChoice({reset})：默认保住当前时刻，换日期才重置，切换后 refreshScenario()。
